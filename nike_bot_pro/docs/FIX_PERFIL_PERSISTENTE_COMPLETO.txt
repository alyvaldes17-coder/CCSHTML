═══════════════════════════════════════════════════════════════════════════════
🚨 PROBLEMA QUE HABÍA
═══════════════════════════════════════════════════════════════════════════════

❌ FLUJO ANTIGUO (BROKEN):

1. Usuario loguea en Chrome manual (Nike.cl)
   → Cookie vtex_session, vtex_segment en Chrome
   → Usuario vé su dashboard

2. Bot hace LOGIN
   → Abre Chrome
   → Espera 15 minutos ("CIERRA CHROME CUANDO TERMINES")
   → Si usuario cierra Chrome, guarda cookies
   → Si no, timeout

3. Bot hace PLAY
   → Abre OTRO Chrome (contexto aislado)
   → SIN cookies
   → SESSION_SEED intenta /checkout/#/cart
   → VTEX dice: "¿Quién eres?" (401 / 403)
   → has_valid_cookies() retorna False
   → Bot aborta: "No hay cookies"

🤔 VERDAD: Hay cookies, pero el bot no las estaba leyendo.
El bot abría un Chrome vacío mientras el usuario tenía otro logueado.

🎯 CONCEPTO CLAVE:

              Las cookies PERSISTEN en el perfil


2️⃣ SINCRONIZACIÓN DE COOKIES (runtime/worker.py línea 232)

✅ NUEVO:
context_cookies = browser.context_cookies()
for cookie in context_cookies:
    session.cookies.set(cookie['name'], cookie['value'])

👉 RESULTADO: Las cookies del perfil pasan a requests.Session
              SESSION_SEED y checkout los ven
              VTEX acepta la sesión


3️⃣ VALIDACIÓN REAL (engines/session_validator.py)

❌ ANTES:
if "vtex_session" not in cookie_names:
    return False

✅ AHORA:
resp = session.get("/api/checkout/pub/orderForm", timeout=5)
if resp.status_code == 200 and "orderFormId" in resp.json():
    return True
return False

👉 RESULTADO: Validamos contra VTEX, no contra nombres de cookies
              Si VTEX dice OK, la sesión es válida
              VTEX cambia cookies? No importa, seguimos siendo válidos
